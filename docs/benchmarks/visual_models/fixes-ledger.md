# Visual-model fixes and optimization ledger

Captured before changing runtime dispatch, 2026-11-22. The original feature-wrapper dispatch, installation order and pip pins are retained. Runtime bug fixes found during validation are recorded below.

The full regression run exposed one pre-existing VPR defect: CosPlace and EigenPlaces stored a string `device` argument unchanged, then accessed `.type`. Both constructors now normalize explicit device arguments with `torch.device(device)`. The same two lines are corrected in `thirdparty/vpr.patch`, which passes a forward apply check against the vendor HEAD. The install-contract hash for that patch was deliberately updated after this fix; all other installer/patch hashes remain the original values. The existing VPR tests verify string/device inputs and batch/single-image equivalence.

EuRoC startup validation exposed asymmetric stereo feature budgets (only the left extractor was boosted), a point-support fallback that stopped too early for sparse depth, failure exits that did not advance the retry count, and reset retaining the relaxed policy. Both SLAM cores now boost/restore both extractors, progressively relax stereo support with a floor of twice the depth-PnP minimum, count those failures, and restore the original checks on reset. For stereo/RGB-D, BA acceptance compares the same left-image reprojection metric before/after (the solver chi2 also contains depth residuals); monocular keeps its original solver-chi2 comparison. All sensors reject failed/nonfinite optimization. Python tests cover policy/reset, BA acceptance and stereo budget transitions; a native C++ test covers the policy/reset and rejection of empty frames.

The Map timing test previously timed random image generation and ORB extraction and required every C++ binding workload to beat Python. It now isolates Map operations using identical inputs and paired alternating samples. The ratio is advisory unless explicitly requested; a saved same-backend baseline can enforce a 3% regression limit. Every failed sample still fails. This corrects benchmark methodology and does not claim a C++ implementation speedup. See [`tests/README.md`](../../../tests/README.md) for commands.

The reproducible inventory is generated by `benchmarking/inventory_visual_models.py`. `tests/data/visual_models/legacy_install_contract.json` records the exact SHA-256 of all 30 existing top-level vendor patches and every existing installer script. The contract test protects those bytes while model migration is staged. A later intentional installer migration must justify its contract update with install equivalence evidence; regenerating the snapshot alone does not prove equivalence.
